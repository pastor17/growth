# 技术方案文档模板

> 用途：架构方案 / 技术调研 / 技术改造方案。写给「评审的人」和「三个月后忘了的自己」看。
> 写作心法：先结论、再背景、再对比，最后风险；别把方案写成代码解说。

## 1. 摘要（一页讲完）

- **要做什么**：一句话
- **为什么做**：一句话（业务价值）
- **怎么做**：一句话（方案要点）
- **风险**：一句话（最大的不确定性）

## 2. 背景与目标

- 业务背景：现状是什么、痛点是什么
- 目标：可衡量的目标（如 P99 < 200ms、QPS 支持 5k）
- 非目标（明确不做什么，防止范围蔓延）

## 3. 现状与约束

- 现有系统架构（附简图）
- 约束条件：团队规模、技术栈、预算、合规、老系统兼容

## 4. 方案设计

### 4.1 方案 A（推荐）

- 整体架构 / 数据流（图 + 文字）
- 关键设计点：模块、存储、一致性、降级
- 为什么这么选

### 4.2 方案 B（对比）

- 与 A 的关键差异
- 不选 B 的理由（数据支撑，而非感觉）

### 4.3 方案对比表

| 维度 | 方案 A | 方案 B | 说明 |
|------|--------|--------|------|
| 成本 |        |        |      |
| 复杂度 |      |        |      |
| 性能 |        |        |      |
| 可维护性 |    |        |      |
| 风险 |        |        |      |

## 5. 选型依据（如果涉及选型）

- 候选清单与筛选标准
- POC 验证了什么、结论数据（附链接）

## 6. 里程碑与排期

| 阶段 | 内容 | 预估 | 依赖 |
|------|------|------|------|
|      |      |      |      |

## 7. 风险与应对

| 风险 | 概率 | 影响 | 应对 / 兜底 |
|------|------|------|-------------|
|      |      |      |             |

## 8. 灰度与回滚

- 发布节奏（灰度比例 / 时间窗）
- 回滚方案与触发条件

## 9. 评审结论

- 评审人 / 日期 / 结论（通过 / 有条件 / 打回）
- 遗留 TODO

## 10. 附录

- 架构图、压测报告、参考资料
