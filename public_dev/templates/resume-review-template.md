# 简历梳理模板（项目经历重构法）

> 用途：跳槽 / 晋升前梳理项目经历。核心方法：把「我做了什么」重构成
> 「背景 → 行动 → 结果（可量化）」的 STAR 式叙述，让面试官 30 秒读懂你的价值。

## 0. 通用原则

- 一件事的价值 = 结果（量化）+ 你的独特贡献（决策 / 取舍 / 带人）
- 不要写流水账：每个项目只留 1–2 个「最能打」的点
- 所有数字要能经得起追问（口径想清楚）

## 1. 项目清单盘点

## 2. 每个项目写三句话（先草稿）

### 项目 1：__________

- **背景**：为什么要做它？当时的业务 / 技术约束是什么？
- **行动**：你负责了什么？做了什么关键决策？放弃了什么方案？（体现取舍）
- **结果**：可量化的产出（性能提升、成本下降、事故减少、业务增长）

### 项目 2：__________（同上）

## 3. 提炼「可量化动词」

把你做过的动作对号入座：

- 架构类：设计 / 重构 / 迁移 / 演进（量级？）
- 稳定性类：把可用性从 __% 提升到 __% / P99 从 __ 降到 __
- 性能类：QPS 从 __ 到 __ / 延迟 / 资源成本下降 __%
- 管理类：带 __ 人 / 从 0 搭起团队 / 推动跨团队项目落地
- 影响力：分享 __ 场 / 文档被 __ 团队使用 / 培养 __ 名同学

## 4. 简历初稿（每个项目 2–3 行定稿）

> 格式：**一句话结果（数字）** + 一句话做法 + 一句话取舍。
> 示例：主导 XX 系统架构演进，支撑峰值 __ 万 QPS，P99 由 __ 降至 __；核心决策是放弃 XX 方案改用 XX（原因一句话），用「多级缓存 + 异步化」平衡成本与性能。

## 5. 面试追问准备（每个数字都要能讲 3 分钟）

- [ ] 这个结果你是如何衡量 / 验证的？
- [ ] 过程中最大的坑是什么？怎么爬出来的？
- [ ] 如果重来一次，你会改什么？（展示复盘能力）

## 6. 自我定位一句话

> 用一句话回答「你是谁」：擅长什么 + 在什么规模验证过 + 想做什么方向。
> （例如：10 年 + 后端，主导过百万级 QPS 系统架构，技术出身连续创业者，正在往 AI 应用架构与团队管理方向深耕。）
